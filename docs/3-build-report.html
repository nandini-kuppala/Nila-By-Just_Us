Nila

An on-device infant monitor: three inference pipelines, two trained models, a Kotlin app that builds and runs. 72 tests pass — 54 on the JVM and 18 on a device — the detector holds 0.992 AUC on infants it has never heard, and the whole thing runs as a foreground service at roughly 0.3% CPU. The reason classifier does not work, and that turned out to be the most useful result in the project.

The finding

The same model, twice, differing only in how the data was split

Identical audio, identical features, identical architecture, identical training schedule. The only change was whether augmented copies of one recording could land on both sides of the train/test boundary.

Before concluding the signal isn't there, we looked for a coarser one

A five-way task on 457 clips is hard. Maybe a simpler question survives an honest split — so we asked four of them, each with a stated hypothesis rather than a fishing expedition.

So the app tells you your baby is crying, for how long, and whether it is building or settling — all measured — and shows the cause estimate labelled as an unvalidated guess with its own AUC printed beside it. ModelCard.kt is generated from these reports, so the reliability the app claims cannot drift from the reliability it was measured to have.

Hard negatives

Validation caught cats setting off the alarm

The first detector scored 0.991 AUC and looked finished. Running it against real room sounds said otherwise: cat vocalisations fired it five times out of eight. That is not surprising — a meow shares an infant cry's F0 range, harmonic structure and rise-fall envelope — but it would have ended a live demo, and worse, it would wake a parent for nothing.

Uniform augmentation cannot fix that; the model already classifies most negatives easily and spends its capacity there. So: score every training negative with the current model, take the hardest 18%, and rebuild with those oversampled. One round.

Three real bugs turned up this way. The golden-vector test found single-precision twiddle accumulation across nine FFT butterfly stages, then found that the fixture itself was rounding its inputs to 7 decimals when the quiet frames of a real recording contain samples around 1e−6. Neither would have thrown; both would have quietly degraded accuracy.

A fourth only appeared under an instrumented test, and it is the same trap in a different library. MediaPipe's GPU delegate constructs happily and then throws GL_INVALID_ENUM on its first frame. Because FaceWatcher only guarded construction, every frame returned "unavailable" and the camera lane silently did nothing — no crash, no error on screen. It now pushes a probe bitmap through before trusting a delegate, exactly as the TFLite runner already did, and falls back to CPU if that fails. Two libraries, one lesson: constructing successfully proves nothing.

The third only appeared on screen. Kotlin binds .format() to the last literal in a + chain, so a multi-line sentence rendered its earlier %.2f placeholders as literal text — in the one paragraph explaining the leakage finding. It compiled, it did not throw, and no test covered it. ModelCardTest now greps for unresolved specifiers, which is the kind of guard you only think to write after being caught.

Deliberately not built

  • Breathing, vitals, apnoea, SIDS. The FDA sent Owlet a warning letter in 2021 over exactly this — the device carried a disclaimer and the FDA held that alerting on a physiological state made it an unapproved medical device anyway.
  • Cry reason as a stated fact. Measured at 0.444 AUC on unseen infants. REASON_TRUSTWORTHY is false and the UI is wired to respect it.
  • Medicine dosing. Depends on weight and formulation. A unit test greps the corpus for anything that looks like a dose and fails if it finds one.
  • Any network call. There is no HTTP client in the dependency graph, and backup is disabled in the manifest so the log cannot leave via a cloud transport either.
